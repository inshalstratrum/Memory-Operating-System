# **🧠 Life OS: Canonical Memory Architecture Blueprint**

## **📖 Overview**

This repository contains the foundational architectural blueprints for **Shali Life OS (Memory OS v5)**.

These documents were synthetically generated by extracting three years of unstructured chat history, technical logs, and project files, and mapping them into a structured, production-grade vector database schema.

**Note for Developers:** These files are *not* the database itself. They are the strict, mathematical **rulebooks** and **schemas** that the Python Ingestion Script and the Langflow Orchestrator must follow to build the database and route AI traffic.

## **📂 The Architecture Files: Why We Built Them & How to Use Them**

To transition from a messy "chat history" into an intelligent, topic-aware **Cognitive Operating System**, we generated four specific blueprint files.

### **1\. Phase 1: Topic Tree & Source Manifest (`phase_1_topic_tree.md`)**

* **Why it was generated:** Raw chat history is a tangled web. We needed a strict ontological map to categorize all knowledge into distinct, logical silos.  
* **How it is useful:** It establishes the **4 Pillars** (Deen, Vessel, Stewardship, Web). When building the Langflow pipeline or the ChromaDB collections, this document dictates exactly which collection a piece of data belongs to.

### **2\. Phase 2: Memory Schema & Semantic Routing (`phase_2_schema_routing.md`)**

* **Why it was generated:** Vector databases (ChromaDB) need strict metadata to filter information, and LLM routers (Langflow) need natural-language rules to direct user prompts.  
* **How it is useful:** \* It provides the exact **JSON Schema** (e.g., `temporal_state`, `confidence_score`) that the Python ingestion script must attach to every text chunk.  
  * It provides the exact **Routing Prompts** you will paste into your Langflow "Smart Router" node to ensure queries about "Spicy Crust" go to the *Stewardship* collection, while queries about "Health" go to the *Vessel* collection.

### **3\. Phase 3: Source Map Integration (`phase_3_source_map.md` / `.json`)**

* **Why it was generated:** For AI auditability. An AI must be able to cite where it learned a fact so it doesn't hallucinate.  
* **How it is useful:** It acts as the Single Point of Truth (SPoT). The Python script uses this mapping to attach the correct original `filename.md` and `project_id` to the vector metadata, allowing Shali to display exactly where she retrieved her information in the PyQt5 UI.

### **4\. Phase 4: Merge Log & Confidence Report (`phase_4_merge_log.md`)**

* **Why it was generated:** Human workflows evolve (e.g., moving from Streamlit to PyQt5). The AI needs to know what is active and what is dead.  
* **How it is useful:** It acts as the ultimate conflict-resolution guide. It tells the system to tag old tools as `deprecated_memory` and current tools as `active_memory`. This prevents Shali from retrieving outdated code or using obsolete project pipelines.

## **🚀 The Next Execution Phase (For Later)**

When development resumes, follow this exact sequence to bring the Memory OS online.

### **Step 1: Configure the Langflow Brain (The Router)**

1. Open the Langflow visual canvas.  
2. Create a **Semantic Router Node** at the start of your conversational flow.  
3. Open `phase_2_schema_routing.md`. Copy the natural-language descriptions for the 4 Pillars and paste them into the Router Node's configuration.  
4. *Result:* Shali can now semantically route user queries to the correct database collection before generating an answer.

### **Step 2: Build the Python Ingestion Engine (The Vectorizer)**

1. Write a Python script (`ingest.py`) to read the raw markdown files from your historical vault.  
2. Implement the chunking strategy: **250-word chunks with a 10-15% overlap**.  
3. Map the chunks using the **JSON Schema** found in `phase_2_schema_routing.md`.  
4. Embed the text using the local `all-MiniLM-L6-v2` embedding model.  
5. Push the embedded vectors into your local **ChromaDB** instance, isolated by the 4 Pillar collections.

### **Step 3: Initialize the Shali Environment (The Boot Sequence)**

1. **Critical Constraint:** You must use Python 3.11 inside a virtual environment (`venv`).  
2. **DLL Crash Prevention:** In your `main.py` or `orchestrator.py`, you **must** execute `import torch` *before* importing `PyQt5`. Failure to do so will result in the `c10.dll` initialization failure.  
3. **Security Test:** Boot the UI and test the Master Security Gate. Ask a question regarding sensitive data. The system must block retrieval unless **PIN 7777** is provided in the thread.
